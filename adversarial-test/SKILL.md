# 对抗性测试

## 核心规则

> 对刚才的代码做一次对抗性测试，重点攻击异常输入、边界值、并发、网络失败和错误假设。发现问题后修复，并补上永久回归测试。

## 适用时机

- 一段新增/修改的代码刚完成并通过了常规测试
- 用于交付前的自我审查，也用于审查他人/历史的代码

## 攻击面清单

按以下维度逐个进攻，每个维度都尝试至少 2~3 种攻击：

### 1. 异常输入
- 未定义类型 / 类型不符的值
- null、undefined、None、NaN、Infinity
- 非法格式、编码问题、超出预期的字符集
- 空对象、缺失字段、多余字段
- 负数、极大数、极小精确值、科学计数法
- 输入超长 / 超大：超大数组、超长字符串、深层嵌套
- 重复元素、全相同元素、逆序元素
- 特殊路径：相对路径/绝对路径/带空格/含 Unicode/含引号
- 恶意载荷：注入类输入（SQL、命令、XSS、XML 外部实体）、zip 炸弹、路径穿越

### 2. 边界值
- 集合长度为 0、1、刚好上限、上限+1
- 索引为最前、最后、越界负索引
- 时间边界：恰好到点、超时临界、跨小时/跨天/跨时区
- 颜色/ASCII/Unicode 组合边界
- 浮点比较：`0.1 + 0.2` 类精度问题、`.toFixed` 精度

### 3. 并发
- 同一函数被并发调用（race condition）
- 共享可变状态、缓存、计数器、单例
- 数据库/文件并发读写
- 两处代码同时写同一资源

### 4. 网络失败
- 超时、连接被拒、DNS 失败
- 响应缺失、延迟到达、乱序、半截响应
- 状态码非 2xx
- 重试逻辑炸掉：无限重试、重试风暴

### 5. 错误假设
- 假设输入总为非空 ⇒ 注入空值
- 假设字典总含某键 ⇒ 删除该键
- 假设某个外部函数总成功 ⇒ 让其抛错
- 假设返回值总为非负 ⇒ 注入负值
- 假设某依赖一定存在 ⇒ 断网/移除依赖

## 工作流程

1. **构造最小攻击输入**，直接执行目标代码（不经过层层包装）
2. **记录实际行为**：崩溃、错误、静默错误结果、性能退化、数据损坏
3. **判定影响等级**：Critical（崩溃/数据损坏/安全漏洞）→ 必须立即修；Major（错误行为给出错误结果）→ 修；Minor（异常但不影响正确性）→ 记录
4. **修复**：遵循 `reproduce-first`（先写复现测试）与 `minimal-change`
5. **补永久回归测试**：每条已修复问题对应一个回归测试，放入项目测试套件
6. **输入回归测试集**：把本次构造的攻击输入保存为测试数据，防止未来回归

## 验收检查

- [ ] 已覆盖异常输入、边界值、并发、网络失败、错误假设五类攻击
- [ ] 每个攻击都构造了可执行的输入并记录了结果
- [ ] Critical/Major 问题已修复
- [ ] 每个已修复问题都有对应的永久回归测试
- [ ] 修复后全量测试通过
