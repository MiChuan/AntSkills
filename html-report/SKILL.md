# 单文件 HTML 报告

## 核心规则

> 不要输出 Markdown。把结果做成一个单文件 HTML，用标签页、流程图和颜色展示重点，生成后直接在浏览器打开。

## 执行步骤

### 1. 收集内容

- 先完成实际工作（分析/审查/测试结果），把内容组织成结构化数据：标题、章节、要点、数据表
- 报告以"给读者看"为目标：先结论后细节，重点高亮

### 2. 生成单文件 HTML

- 所有内容、样式、脚本内联在一个 `.html` 文件里
  - CSS 用 `<style>` 内联，JavaScript 用 `<script>` 内联
  - 不引用外部文件、外部 CDN、外部字体（离线也能打开）
- 结构要求：
  - **标签页（Tabs）**：多个内容区用标签页切换（JS 实现），每页一个主题
  - **流程图（Flowchart）**：用内联 CSS/SVG 绘制流程、依赖关系或决策分支
  - **颜色高亮**：用语义颜色突出严重性：红色=高危/错误，橙色=警告/中危，绿色=正常/通过，蓝色=信息。关键数字、风险等级、结论用颜色强强调

### 3. 在浏览器打开

- 二选一：
  - `start <文件>`（Windows）/ `open <文件>`（macOS）直接打开
  - 打印出文件路径，提示用户手动打开
- 运行后确认浏览器成功打开，并在你的回复里附上文件路径

### 4. 报告之外的对话

- 正文可以用一句话给出结论与文件路径
- 其余细节都在 HTML 里，不再用 Markdown 重复输出

## 视觉指南

- 默认浅色背景、干净排版；内容密度高时用卡片/表格分组
- 标签页在顶部的醒目位置，当前活动标签高亮
- 流程图使用明确的箭头走向，路径可读
- 不使用过多的花哨动画；重点在于信息呈现

## 验收检查

- [ ] 输出为单个 `.html` 文件，无外部依赖
- [ ] 有标签页组织内容，多主题可切换
- [ ] 有关键流程图（流程/依赖/决策）
- [ ] 严重程度/结论用颜色体现
- [ ] 已在浏览器打开，或给出可直接打开的路径
