# 重构前固定行为

## 核心规则

> 先不要重构。先补一组测试，固定当前所有行为，包括奇怪的边界情况。测试必须在原代码上全部通过。

## 执行步骤

### 1. 枚举可观测行为

通读目标模块，列出所有可被外部观测到的行为，包括：

- 正常输入对应的输出
- 边界值：空值、0、负数、最大值、超长字符串、空集合、最小集合
- 奇怪的边界情况：历史遗留行为、看起来"不合理"但一直如此的结果、隐式约定（如"传入 None 也返回 []"）
- 错误行为：抛出的异常类型与消息、副作用、日志、返回值约定

### 2. 为每个行为写一个测试

- 测试断言的是"当前实际行为"，而不是"我认为应该的行为"
- 格式：`input → actual_output`，把每个固定行为变成断言
- 若项目无测试设施，用独立的脚本逐项断言

### 3. 在原代码上跑全部测试

- 必须全绿。任何一条失败都说明测试写错或行为记录错，修正测试直到全绿
- 全绿的意义：之后任何重构导致行为变化时，这些测试会立刻标红

### 4. 重构并回归

- 重构以这些测试为安全网
- 重构后全部通过即视为"行为未变"
- 不要在同一个改动里既重构又改行为；行为改变必须作为单独的、显式标注的步骤

## 验收检查

- [ ] 测试覆盖正常路径 + 边界值 + 奇怪的边界情况 + 错误路径
- [ ] 测试在原代码上全部通过
- [ ] 测试断言的是当前行为，没有预设立场
- [ ] 重构只改变内部实现，测试全绿表示行为不变
